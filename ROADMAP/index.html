    ROADMAP — loop-driven delivery plan·

    Executed by tiny as a worker loop + supervisor loop (two slots). Each milestone has a hard gate — the loop may not advance past a gate without the evidence named there. Flash/monitor happen on cagatay-mac (/dev/cu.usbmodem5C843358881); the loop runs on this machine and has the port.

    Ground rules for the loops·

    • Never flash before recovery/stock-firmware-32MB.bin + .sha256 exist and match (M0 includes verifying the dump that is currently being read).
    • Prefer 460800 baud for writes; on "serial noise/corruption" drop to 115200. Never two esptool/monitor processes on the port at once.
    • Commit per green step; push per milestone; journal decisions in docs/JOURNAL.md.
    • Vendor sources are read-only reference — adaptations are COPIES into firmware/.
    • Anything touching ~/tinyai-id (the /api/devices/ask route) gets its own branch + cagatay review before deploy; the firmware must keep its fallback path.

    M0 — toolchain + vendor demo builds & runs (gate: demo on hardware)·

    • install ESP-IDF v5.4 (~/esp/esp-idf-v5.4), idf.py --version green
    • verify flash dump: size 33554432, write .sha256, copy to Mac mini (mesh) for a second host
    • build vendor/Sticky_dashboard_demo unmodified; flash; photo-verify pages render + touch works (use_computer screenshot of monitor output + status via serial)
    • record actual measured refresh timings (gray4 full / mono full / partial) in JOURNAL

    M1 — skeleton firmware boots (gate: our app runs, display + button + buzzer alive)·

    • firmware/ builds standalone reusing vendor components (EXTRA_COMPONENT_DIRS)
    • tiny_boot (power latch! mic-mux fix), board bring-up, "tiny" splash card on e-ink
    • serial console clean at 115200, version banner, idf.py monitor workflow scripted in tools/

    M2 — display + touch layer (gate: card-spec JSON renders; tap detected)·

    • tiny_display: canvas text/list/kv/chart/image primitives, refresh policy, 180° rotation handled
    • tiny_touch: GT911 orientation calibrated on OUR unit; touch regions
    • host tool tools/render_card.py --port … pushes a card over serial for bench tests (pre-Wi-Fi)

    M3 — Wi-Fi + provisioning + node loop (gate: device visible in tiny fleet, envelope round-trip)·

    • tiny_config (NVS), tiny_provision (AP portal + QR card), tiny_node (heartbeat/poll/reply)
    • enroll a real device row (POST /api/devices via CLI), provision over the portal
    • prove: use_device invoke → status command → reply arrives — the Sticky answers from any tiny surface
    • heartbeat-401 path tested (revoke → portal reopens)

    M4 — the agent tools (gate: all three headline tools work end-to-end)·

    • screenshot: shadow FB → BMP → /api/media → reply URL → the agent can SEE the screen
    • render_ui: full card spec incl. buttons; ui_tap events flow back (verify event route shape)
    • image/stream: server-dithered frames; measured cadence documented
    • say: chime library; buzzer-PCM experiment (timeboxed, journal the verdict)

    M5 — voice ask (gate: hold button, speak, answer card appears)·

    • tiny_audio: PDM capture (mic-mux fix proven post-deep-sleep), WAV, upload
    • backend: POST /api/devices/ask in ~/tinyai-id (branch + review) — transcribe + agent turn
    • fallback path (transcript + relay envelope) implemented FIRST, /ask second

    M6 — OTA + power (gate: OTA self-update survives + battery life estimate)·

    • partitions 32MB (factory + A/B + assets), tiny_ota (sha256, host pinning), trial-boot/rollback in tiny_boot
    • sleep policy: display persists, EXT1 wake, adaptive poll on battery; measure mA in each state
    • publish OTA channel sticky-dev via /api/firmware/manifest

    M7 — polish + registry (gate: daily-driver on the fridge)·

    • status bar (battery/RSSI/time via partial refresh), sleep card, error cards (portal QR on 401)
    • docs pass; demo video; consider playground-registry flash-mode PR ("tiny" in Seeed's catalog — memory #364)

    Supervisor loop duties·

    • watch worker journal each pass; unstick (kill stale port holders, retry builds), enforce gates
    • verify commits are pushed; escalate to cagatay (use_notify) on: gate failure ×2, any flash-erase beyond app partitions, anything touching tinyai-id deploy
    • keep docs/JOURNAL.md honest — every gate needs evidence (measurement, photo, or transcript), not assertion
