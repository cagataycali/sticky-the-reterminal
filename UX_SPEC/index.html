    UX Spec — the stickyOS interaction contract·

    Owner: the product-designer loop. Version 1.6 (2026-08-26) — §15 chat conversation surface (ask lifecycle, follow-up context, DM consent gate); v1.5 added §13 sound rules, §14 anim law, §7 settings IA v2. This file is the single source of truth for how the Sticky feels. The builder implements it; verdicts against it land in ANSWERS.md. Every rule carries a WHY, and every rule carries a status: SPECIFIED → BUILT → VERIFIED-ON-GLASS (only an owner-loop screenshot or probe receipt flips the last one).

    Seed law from cagatay (2026-08-26, verbatim intent — everything else expands it):

    1. Swipe bottom → up = HOME, from anywhere.
    2. Swipe left → right = previous / back.
    3. Gestures are context-dependent — in the gallery, horizontal swipes mean previous/next image, not page nav.
    4. Settings must be truly editable on-device.

    0. Physics and vocabulary the spec obeys·

    • Full refresh ~1–2 s; partial ~300–500 ms; ghosting after ~20 partials; ~2 Hz animation ceiling. A gesture may therefore trigger at most one panel-visible response, and the ack must be felt before it is seen (buzzer <60 ms, visual <500 ms) — the "touch feels dead" incident (TOUCH_AUDIT) is the founding lesson.
    • Coordinate spaces: touch and screenshot live in panel space (800×480 landscape, invariant under rotation). Gestures are interpreted in layout space — "up" means visually up in the current rotation, exactly as the M12 scroll gesture already does (tiny_display_scroll_gesture maps the vector). WHY: a human swipes relative to what they see, not to the panel's wiring.
    • Feedback vocabulary (three words, never more):
    • single blip + visual ack = accepted, something happened;
    • double short blip = recognized but refused — a dead end, and the double blip IS the explanation a 2 Hz panel can afford;
    • silence = below thresholds, not a gesture. Nothing else is silent. WHY: on e-ink the sound arrives 10× sooner than any pixel can.

    1. Zones and thresholds (layout space)·

    name definition why
    tap slop movement < 24 px (shipped) finger roll ≠ swipe
    swipe travel ≥ 120 px dominant axis scroll steps and slips stay distinct
    axis dominance dominant ≥ 2× the other axis diagonal = ambiguous = silence
    bottom band start-y in the last 56 px of layout height (= the touch-bar strip) edge-origin marks NAV intent; a button tap moves <24 px so the two can never collide
    left band start-x in the first 48 px of layout width iOS back-swipe muscle memory
    long-press ≥ 750 ms, < slop movement, fire AT threshold with blip reserved (context menu, phase 2)

    The conflict rule, decided: edge-originated swipes are NAV; mid-content swipes are CONTENT. Bottom-band-up = home even on a scrollable card — a scroll swipe naturally starts mid-body, and content under the touch bar is reachable by scrolling down from above. WHY: one spatial rule resolves every home-vs-scroll ambiguity without modes, and it is defensible in one sentence.

    2. The gesture grammar (gesture × context → action)·

    Contexts: ring page (home/status/sensors/settings root), pushed card (wifi list, message thread, ble, any relay-rendered card), gallery, keyboard, streaming answer, locked (pocket, P-1).

    gesture ring page pushed card gallery keyboard streaming locked
    bottom-band swipe ↑ HOME (law #1) HOME HOME HOME (= cancel, don't save) blip-defer¹ ignored²
    left-band swipe → back = ring prev BACK (pop) (law #2) BACK (exit gallery) dead-end ‼ (keys own the glass) blip-defer¹ ignored²
    mid-content swipe ← / → ring next / prev → = back, ← = dead-end ‼ next / prev IMAGE (law #3) silence³ blip-defer¹ ignored²
    mid-content swipe ↑ / ↓ scroll if overflowing (M12, shipped — do not break), else dead-end ‼ same caption show/hide reserved; v1 dead-end ‼ silence³ auto-scroll owns the tail¹ ignored²
    tap on button/row/key activate (shipped) activate button parity (Prev/Next/Back) type (ack = value line) blip-defer¹ ignored²
    tap on empty canvas silence (logged) silence toggle caption silence blip-defer¹ ignored²
    long-press (touch) reserved, phase 2 — silence until then ← ← ← ← ignored²

    ‼ dead-end = double blip, nothing moves. WHY: a recognized gesture that does nothing must say it was heard, or the panel reads as broken.

    ¹ Streaming answer: the stream owns the display (STREAMING_UI rule 7); no tap regions exist mid-stream by design. Every touch gets a single blip and is discarded — acknowledged, not obeyed. The ONE exit is physical: long-press AI (2 s) aborts the stream (stream_end, append "[interrupted]") and goes home. WHY: a stream is bounded (≤30 s + stall watchdog), so deferring touch is predictable; but no state may ever hold the device with zero exits, and the exit must work through fabric and gloves — hence a button, not a gesture.

    ² Locked (pocket, P-1): touch fully ignored, no blips (a buzzing pocket is noise, and buzzer-on-every-fabric-brush drains the 750 mAh pack). No voice capture starts while locked. Unlock = hold UP + DOWN together 1 s → single blip + wake card. WHY: a chord is the one input fabric cannot forge.

    ³ Keyboard silence exception: horizontal/vertical swipes over the key area are silence, not dead-end — typing drift would otherwise double-blip constantly. The keyboard's own cancel/ok keys and the bottom-band home swipe are its exits.

    Rotation invariant: the table above is layout-space; the router maps through the current rotation before classifying (the scroll gesture already does; NAV must ride the same transform). A gesture mid-rotation-commit is dropped like a tap on a changed card-gen.

    3. Physical button parity (accessibility + gloves + pocket)·

    Every gesture verb has a button path — gestures are an optimization, never the only door:

    intent gesture button path
    home bottom-band ↑ long-press AI (shipped)
    back / prev left-band → UP click on pushed card = back; on ring = prev page (shipped ring)
    next mid ← DOWN click (shipped ring; = next image in gallery)
    scroll mid ↑/↓ UP/DOWN on overflowing card (shipped)
    ask tap Speak / hold AI hold AI (shipped)
    abort stream — (deliberately none) long-press AI 2 s
    unlock — (deliberately none) UP+DOWN chord 1 s

    WHY: the audit's P-1 pocket case and glove/winter use both reduce to "the three keys must be able to do everything destructive or rescuing."

    4. Navigation model — ring and stack, reconciled·

    • The ring is the set of top-level pages: home ▸ status ▸ sensors ▸ settings (+ gallery when it lands). Ring moves (UP/DOWN, horizontal swipes on a ring page) replace the stack top — depth stays 1. WHY: cycling must never build a 47-deep history of status pages.
    • Opens push: settings→wifi, chats→thread, any keyboard, any relay card the shell didn't originate. Back pops. Home clears to [home].
    • A relay render_ui card arrives as a pushed card — back from it returns to what the human was doing. WHY: a remote agent may interject but never steal the human's place.
    • Stack depth 8 (shipped) is ample; overflow drops the oldest non-home entry.

    5. Feedback rules (the 500 ms contract)·

    1. Buzz before anything that can block; visual ack within 500 ms via region partial (shipped invert-ack) — except keyboard keys, where the value line IS the ack (shipped).
    2. Dead ends double-blip (new). Locked state never blips (new).
    3. An action that will take >2 s (ask, wifi join, image fetch) must leave a pending mark on the glass within 500 ms (streaming chrome, "joining…" row, caption "fetching…"). WHY: e-ink cannot spin a spinner; a written word is our progress indicator.
    4. Every refusal names its reason on the glass (house honesty rule).

    6. Cards — typography & hierarchy rules·

    • One idea per card; title ≤ ~28 chars before fold; body is the only scrollable region; footer is metadata, never content; ≤4 buttons.
    • Contrast ladder: Black on White for content, DarkGray for chrome/hairlines, LightGray fills only for "user bubble" / selection. WHY: 4-gray is a hierarchy budget, not a palette.
    • Streaming chat chrome per STREAMING_UI layer 4 (user bubble right/LightGray, assistant left/outlined; caret only while bytes may arrive). Bubble max-width = 70% of body width (v1.2, R-3): shrink-to-fit when short, wrap at 70% when long — a 28-char column on an 800 px panel reads as a receipt, not a conversation.
    • Emoji/glyphs with no 4-gray rendering are stripped in chat bubbles, never folded to "?" (v1.3, R-4): "Hey! ?" is a different sentence than "Hey! 👋" — absence is honest, substitution changes tone. Content characters keep the fold-table "?".

    7. Settings — information architecture (law #4: truly editable)·

    Settings root becomes a menu (rows, not a kv dump; current kv view moves to About):

    Settings
├─ 🔕 Snooze     → FIRST ROW, one tap cycles: Off → 1h → until-wake → forever.
│                 Row note shows the countdown/state. Mutes all LOCAL sounds
│                 (§13 tier L); never mutes owner-hand `play`. WHY first: the
│                 owner's own words — "cut the voice of the beeps when i click
│                 somewhere" — and the acceptance is ≤2 taps from anywhere
│                 (home → Settings → Snooze).
├─ Sounds       → volume tier (duty): Soft / Normal · per-event toggles:
│                 tap / ack / error / dm / boot jingle
├─ Display      → rotation: Auto / 0 / 90 / 180 / 270 (lock = manual mode,
│                 same semantics as `rotate` verb) · theme: Light / Dark (invert)
│                 · glance-on-wake: On / Off
├─ Wi-Fi        → networks list: join (keyboard), forget, move-up priority;
│                 stored nets in NVS; passwords render as dots, always
├─ Agent        → thinkers list (M-A7: prompt · every X · last-run · on/off,
│                 [New thinker] → keyboard → interval menu) · ask history On/Off
├─ Power        → sleep timeout: 2 / 5 / 15 min / Never · eco threshold display
├─ Lock         → pocket lockout: Auto (IMU) / Off · shows unlock chord hint
└─ About        → fw, commit, channel, device id, mac, ssid/rssi, battery health

    Every editable row states its current value in the row note (menu note field, shipped) so the glass never hides state behind a tap. Toggles commit on tap with single blip + row re-render (partial) + an NVS scalar + a set <key> <val> relay twin, so every on-glass edit is also scriptable. WHY: a settings page that requires a phone is an admission the device isn't sovereign — and a setting without a relay twin is untestable by the verdict rail.

    8. Gallery — interaction model (with builder M-A4)·

    • v1 is a single-image pager, newest first: open → latest image full-bleed (1-bit, server-dithered), caption + glance bar toggled by empty-canvas tap.
    • Horizontal swipes / UP/DOWN = prev/next (law #3). Bottom-band ↑ = home. Left-band → = back. On-glass Prev/Next/Back buttons for parity.
    • Every image lands with a full refresh (an image IS a new page; partial ghosting over a photo is unacceptable).
    • Ends of the roll are dead ends (double blip), never wraparound. WHY: a loop of N images with 1–2 s page turns makes "am I at the start?" unanswerable.
    • Offline (P-2): cached rasters stay browsable; glance bar shows w-; an uncached image says "not cached — offline", never a blank frame.

    9. Error & offline states (what the device SAYS)·

    state the glass says why
    wifi down glance w-; current card persists (e-ink superpower) ambient truth, no modal panic
    ask fails / 422 "didn't catch that" card (shipped) / error card naming the HTTP reason a refusal names its reason
    ask never left the device (transport, st ≤ 0) "couldn't reach tiny — your question was NOT sent; try again" + free-heap in footer. The word "Backend" is forbidden here an error message must name the true culprit; "Backend said -1" attributes to the backend words it never said (owner-hit P1, 2026-08-26 02:5xZ)
    stream stalls "[stream stalled]" appended, caret removed (shipped) a cut answer must say it is cut
    relay silent nothing changes on glass device-initiated surfaces only; silence upstream isn't the human's problem
    image fetch fails "couldn't fetch image ()" honest-void never a half-blitted frame
    auth-halt rescue portal card + QR (shipped) recovery without a cable

    11. Pocket lockout — the state machine (P-1, safety-critical)·

    Pocket-carry's one unforgivable failure: fabric holds the AI button, 15 s of audio records and uploads. Lockout is therefore a SAFETY feature, not a convenience.

    States: UNLOCKED ⇄ LOCKED (no third state; "locking…" does not exist on e-ink).

    Entry to LOCKED (any one): - IMU: face-down ≥ 3 s, OR sustained walking-motion signature ≥ 5 s while no touch for 30 s (thresholds are firmware constants, tuned on-device, named in code) - Manual: Settings ▸ Lock, or a future button chord

    While LOCKED: - Touch controller: events discarded at the router (not deshielded per-page) - AI button: hold does NOT start voice capture — the one rule that is the point. Short-press wakes the glass to the glance card (§12) with a lock glyph. - UP/DOWN: page nothing; they are the unlock chord only - Buzzer: chirps still allowed (notification while pocketed = the product working) - Relay verbs: STILL ANSWER (status/screenshot/say/render_ui) — lockout guards the device's own inputs, not the owner's remote reach. voice verb refuses while locked with an honest sentence (remote-triggered recording from a pocket is the same privacy incident with extra steps).

    Exit: hold UP+DOWN together 1 s → full refresh → last card restored.

    Truth surface: status JSON gains "locked":true|false (spec-mandated field); the glance card shows a lock glyph. ACCEPTANCE (needs D-UX0 + a lock/unlock test verb or Settings toggle): lock → press ai hold must NOT record (no upload event, log line names the refusal) → tap anywhere discarded → status.locked true → unlock chord → status.locked false and touch live again.

    12. Glance card — wake-on-lift (P-4)·

    The 80% interaction of a pocket device: pull it out, look, put it back. Target: glanceable in under 2 s from wake trigger.

    • Trigger: IMU lift-to-look signature, or any button short-press
    • Content (one partial refresh, no full flash if the panel already holds a card): time · battery% · wifi glyph · unread count · lock glyph when locked. One line, top of glass, over whatever card was last shown (e-ink keeps it for free).
    • NOT a page: it draws over the status strip zone and expires from the nav model — BACK/scroll/tap all act on the underlying card.
    • ACCEPTANCE: from sleep, button-press → glance strip visible < 2 s (measured by log timestamps wake→refresh-complete); from awake, strip updates by partial refresh only (no full-panel flash receipt).

    13. Sound rules — ratified (M-A6)·

    The buzzer (GPIO48, LEDC PWM) is the device's fastest output — sound lands ~10× before any pixel (§0). These rules are LAW for every current chime and the coming RTTTL engine.

    Sound tiers — every sound the device can make belongs to exactly one:

    tier what examples governed by
    L — local UI feedback consequence of the owner's own touch/button tap blip, ack, dead-end double blip, error Snooze mutes; LOCKED mutes (see below); ≤ 400 ms
    N — notifications device-initiated, tells a pocketed owner something arrived dm motif, thinker-result chime, low-battery Snooze mutes; LOCKED allows (a notification while pocketed is the product working, §11); ≤ 400 ms
    O — owner's hand explicitly commanded over the relay play <rtttl>, say with chime NOTHING mutes it — the owner pressing play IS consent; 64-note cap
    B — boot jingle once per cold boot 4-note motif (M-A6c beat-sync gate) the one exception to 400 ms; Snooze-forever suppresses it

    Ratified reconciliation of M-A6 "silent while pocket-locked" vs §11 "chirps still allowed": both were right about different tiers. LOCKED kills tier L trivially (locked discards the inputs that would cause feedback) and keeps tier N — a pocket device that can't chirp an arrival is a brick with better battery life. The owner's public-silence need is served by Snooze (§7 first row), which is a deliberate one-tap act, not a side effect of pocketing. WHY this split: lockout guards inputs (privacy), snooze guards outputs (courtesy) — collapsing them makes one need destroy the other.

    Motif taste guide (leitmotif, not alarm): ack = rising major third; error = falling minor second; dm = 4-note motif; dead-end = the double blip, unchanged — it is vocabulary (§0), not music. All motifs live in the B4–C7 resonance sweet spot; envelope via LEDC fade (30 ms attack / 80 ms decay) so chimes ring instead of buzz. WHY leitmotifs: a sound the owner can name without looking replaces a screen glance — that is the entire budget argument for a buzzer on a 2 Hz panel.

    Refusals are honest: a tune over 64 notes is refused naming its byte count; play while snoozed still plays (tier O) and the reply says so.

    14. Animation usage rules (M-A6b — when may pixels move?)·

    Physics: ~2 Hz ceiling, ghosting after ~20 open-loop partials (§0). An animation is therefore a budgeted act, never decoration.

    • Closed-loop anims ("closed":true — every pixel returns to its origin state each cycle: blink, invert-pulse, two-phase breathe) accumulate ~zero ghosting because displacement cancels; the player skips wipe_every. These are the ONLY anims allowed to run indefinitely (idle home creature, thinking pulse). WHY: an idle screen that slowly turns grey teaches the owner the device is broken.
    • Open-loop anims (travel, trails, typers) keep the wipe law (wipe_every mandatory) and must be event-bound: they play because something happened (boot, answer arriving, ota progress) and they END — no open-loop anim outlives its event.
    • Dirty-bbox is a cost dial: compact motion (~120 px box) sustains ~3 fps; full-width partials cap at ~2 fps. stickyOS anims are creatures and glyphs, not scene changes — a scene change is a page turn and gets a full refresh.
    • Streaming answers own the panel: no concurrent anim while the typer runs (G6 already defers touch; pixels defer too). One moving thing at a time — the eye on e-ink can't arbitrate two.
    • Beat-sync (M-A6c) inherits its anim's class: a closed-loop 2-frame pulse synced to a jingle is the sanctioned WOW; sound carries the liveliness the panel cannot (§0). Locked/snoozed states strip the tune per §13 and the anim plays silent.

    15. Chat — the conversation surface (M-A1/M-S5 successor spec)·

    Two different things wear bubbles; the spec refuses to blur them: - Ask thread — owner ⇄ their own agent, born from Speak/Type/ask. Ephemeral by default; §7 Agent ▸ ask-history toggles local persistence. - DM thread — owner ⇄ another tiny.technology user (Chats ▸ m:inbox). Server truth; the device is a viewport, never the store. WHY: an agent answer and a human message carry different obligations — a human's words must never be summarized, aged out, or restyled by the device.

    Ask lifecycle (one law, five moments): 1. Receipt — the question becomes the user bubble before any network round-trip (shipped: stream_render seeds s_stream_q). A question the glass didn't echo is a question the owner can't trust was heard. 2. Thinking — caret alone, no empty assistant bubble (shipped). The caret is the only legal "spinner" on this hardware. 3. Streaming — G6 rules: stream owns the display, auto-scroll owns the tail, physical long-press-AI is the one exit. 4. Settle — stream end = ONE full refresh (ghost purge + caret removal, shipped) AND the moment tap regions return. Touch bar on a settled ask card: [Speak] [Type] [Home] — a settled answer is an invitation to follow up, in place. 5. Follow-up — Speak/Type from a settled ask card appends to the SAME visual thread (new user bubble below), and the ask request carries the prior turns of THIS thread as context (bounded: last 4 turns or 2KB, oldest dropped first). WHY: "what about in celsius?" must work; an amnesiac chat page is a text card in costume. DEPENDENCY: if /api/devices/ask cannot accept a context array today, firmware ships the visual thread first and the context field is filed in QUESTIONS.md — the UI contract must not wait on the backend.

    Thread typography at settle (extends §6): - Newest turn is the tail; entering a thread lands scrolled to the TAIL, not the top (a conversation's present tense is its bottom line). - Older turns scroll away under M12 rules; the scrollbar is the only history indicator. No timestamps inside bubbles — relative time lives in the inbox list row only. WHY: on 4-gray every bubble byte competes with the answer. - An ask that arrives while a DIFFERENT card is showing (relay ask) still takes the panel — asks are owner-initiated by definition, never a surprise.

    Inbox (DMs) rules: rows = sender + relative time + first line (fold rules §6); unread = Black dot, read = none — binary, no counts per row (the §12 glance strip owns the aggregate). Opening a thread marks read server-side (shipped semantics); the device never marks read on glance-strip evidence alone. Reply from a DM thread uses the keyboard; cancel returns to the SAME thread unsent (shipped, tiny_shell.cpp:426). DM send is the one action on this device that reaches another human: the composer's OK label reads "Send" on DM threads, never "ok". WHY: the label is the last consent gate.
