    API CONTRACT — exact wire shapes (source: ~/tinyai-id routes + ~/strands-nicla/firmware)·

    Base URL from config (api, default https://tiny.technology). All device verbs authenticate with deviceId + token IN THE JSON BODY (not headers). Every request: 15 s timeout, TLS. All bodies Content-Type: application/json.

    Heartbeat — every 30 s (≈60 s when idle, 0.14.14+)·

    POST /api/devices/heartbeat
{"deviceId":"…","token":"tind_…","capabilities":["render_ui","screenshot","ask","say","sensors","image","stream","sleep","ota","messages"]}
→ 200 {ok:true}
→ 200 {ok:true,"unread":3}   when the beat opts in with "wantUnread":"1" — the DM badge rides the beat, no extra request
→ 401  = revoked/rotated — but never erase identity on ONE 401 (blips happen):
         3 consecutive = auth-halt + rescue portal (0.14.12); do NOT retry-loop

    Relay poll — every 5 s active · 60 s idle (adaptive, 0.14.14+)·

    Cadence is adaptive since 0.14.14: 5 s polling while active (an envelope, tap, or boot in the last 2 minutes), stretching to 60 s after two quiet minutes — cutting idle TLS handshakes ~17k→~3.4k/day on the 750 mAh pack. Boot and wake always start ACTIVE (never wake into a 60 s hole), the auth-halted slow path is untouched, and status JSON exposes poll_cadence so the claim is a read, not a belief. Verification note from the bench: the observable for cadence is probe-2 pickup delay, not the field alone — the probe envelope itself is activity, so a single probe always reports a device it just woke up. 

    PUT /api/devices/relay
{"deviceId":"…","token":"…","max":5}
→ {"messages":[{"id":"env_…","payload":"<SERIALIZED STRING: {\"type\":\"invoke\",\"prompt\":\"…\"}>"}]}  ⚠ payload is a STRING containing JSON (sender JSON.stringify) — parse it, then read .prompt
    Execute in order; unknown command → reply help text (never silence).

    Relay reply — per envelope·

    PATCH /api/devices/relay
{"deviceId":"…","token":"…","inReplyTo":"env_…","payload":"<SERIALIZED JSON STRING ≤8000B>"}
payload string decodes to: {"result":"…"[, "images":[{"url":"https://…","format":"bmp"}]]}
    ⚠ payload is a string containing JSON, not nested JSON — Nicla's serializer is the reference.

    Media upload·

    POST /api/media
{"deviceId":"…","token":"…","data":"<base64>","contentType":"image/bmp" | "audio/wav"}
→ {"url":"https://plugin.tiny.technology/…"}   (note: different host than api — matters for OTA host pinning)
    b64 of n bytes = 4·⌈n/3⌉; with 8MB PSRAM we buffer whole (≤1MB artifacts) via esp_http_client; chunked-TE streaming is the fallback for bigger.

    OTA channel pointer·

    PUT /api/firmware/manifest
{"deviceId":"…","token":"…","channel":"sticky-stable"}
→ {"bundle":{"url":"https://…manifest.json","sha256":"…"}}
    Manifest → files[] each with sha256; hosts must be in the pinned allowlist (tiny.technology, plugin.tiny.technology). Downgrade refusal (0.14.9; the fix for an audited hazard): the original trigger was direction-blind (strcmp difference, not newer) — integrity fully verified, direction unchecked, so a stale pointer would have been installed as faithfully as a fresh one. Since 0.14.9 the device compares versions numerically (MAJOR.MINOR.PATCH[-mN]; unparseable = INCOMPARABLE = refuse, fail closed) and stages only when the pointer is newer — unless the bundle carries force:"1", which installs and logs loudly. force lives as channel state (migration 0035): set at publish time, served in every bundle read, self-clearing on the next forward publish — closing a cross-guard deadlock the audit caught, where the publish rail allowed a forced rollback but dropped the flag the install rail needed to accept it: two guards that individually worked and jointly wedged. The refusal reply is an actionable sentence. The publisher's ancestry check (discipline rule 5) remains in force, the publish route itself now 409s a backwards pointer (force:true = an intentional rollback, spelled out at publish time), and the dashboard's ota action opens a 30-minute watch: fw_before is captured by a fresh probe, every parsed status receipt afterwards feeds the redeem, and the verdict is rendered — ⬆✅ upgraded, ⬆🚨 DOWNGRADED, or ⌛ expired-unredeemed, never silence. Three enforcement points (publish, install, watch), each with its own receipt.

    /api/devices/ask — shipped in M5, full tools since phase-3 gate #1·

    POST /api/devices/ask
{"deviceId":"…","token":"…","audioUrl":"https://…"} | {"…","text":"what's on my calendar"}
→ {"text":"…", "card":{…render_ui spec…}}       (transcribe when audioUrl, then owner-scoped agent turn)
    Design follows transcript/route.ts (device-token auth, no session, off IP limiter, worker resolves owner from token hash). The turn runs the owner's full agent (tools, memory, cross-device reach). Runtime note: this route (and job-run) lives on the Node runtime, not Vercel Edge — Edge's 25 s first-byte deadline on non-streaming responses 504'd every long agent turn; the worker-budget bump alone did not fix it.

    /api/devices/messages — the DM rail on a device token (option B, 2026-08-26)·

    POST /api/devices/messages
{"deviceId":"…","token":"…","op":"unread"}                    → {"unread":0,"from":[]}
{"deviceId":"…","token":"…","op":"inbox"}                     → owner's threads + unread counts
{"deviceId":"…","token":"…","op":"thread","with":"<login>"}   → one conversation (MARKS READ platform-wide)
{"deviceId":"…","token":"…","op":"send","to":"…","body":"…"}  → sends as the owner, marked "via <device name>"
    Before this route, every message endpoint was owner-Bearer and the glass could only be a face for the inbox (owner-side pusher). Now the device credential reaches the rail directly — worker-side the ops dispatch in-process to the existing DM handler classes, so send inherits every guardrail by construction (2000-char cap, 100/day, no self-DM, attachment allowlist). Probe receipts on the real token: bad token → 401 with no oracle, bad recipient → 404 through the full send chain, bad op / missing with → 400s. 10 s bound; a 503 is never masked as an empty inbox. The read side effect of thread is unchanged and sacred — fetch only on a real human open. The unread badge rides the heartbeat (opt-in wantUnread, above), and since 0.14.7 the firmware itself speaks this route: the on-device messages app fetches inbox and threads with the device token — it shipped as grammar v1 (an id namespace, not a new card type).

    Provisioning portal (device-side server, Nicla-compatible)·

    softAP  SSID tiny-XXXX (XXXX = FNV-1a over full MAC — Nicla lesson: suffix of serial collides)
        WPA2 key "tinysetup", 192.168.4.1
GET  /info  → {"kind":"reterminal-sticky","name":…,"mac":…,"version":…,"provisioned":bool}
POST /setup {device_id, token[, api, name], networks:[{ssid,key},…] | ssid,key}
        → save to NVS (merge semantics: upsert networks, scalars overwrite) → 200 → reboot
GET  /      → minimal HTML form (manual fallback)
    The same portal has two entries (since 0.14.12): first boot (nothing in NVS, AP only) and rescue — after a 3-strike auth-halt the live STA widens to APSTA and raises the identical /setup → merge → reboot contract, so a re-issued token reaches a bricked-auth device with no serial cable and iOS onboarding code unchanged. STA stays associated in rescue, so a 401 that was a blip self-heals with the portal still up; the glass shows SSID + steps, a fallback card if APSTA itself fails (the panel is never silent), and re-entry is idempotent. One audited hole is on the fix queue: the rescue card's text sits at 468 bytes of a 512-byte buffer — close enough to blank the panel in exactly the path that exists because everything else failed; filed by the truncation sweep, honest here until fixed.

    M-A8 /api/frames — the remote render rail (dashboard, source 1) (2026-08-26)·

    Server-rendered animation for tiny_stream_play(manifest_url, interval_s, max_frames) (firmware/main/tiny/tiny_stream.h — the contract this shape serves). The dashboard rasterizes anim-grammar JSON (docs/research/EINK_ANIMATION.md §4) with Pillow and packs frames through the SAME dither.py packers as /api/dither — canvas-space bytes, the firmware-confirmed format. The device stays a dumb pixel-pusher.

    POST /api/frames (WebAuthn session required)·

    Body = one anim spec: 

    {"anim_id":"bounce","version":1,"mode":"1bit_partial","frame_budget_ms":500,"loop":1,
 "background":"white",
 "frames":[{"op":"rect","tile":{"x":100,"y":300,"w":80,"h":80},"color":"black"},
           {"op":"blit","tile":{"x":40,"y":200,"w":48,"h":64},"glyph":"H"},
           {"op":"delay","ms":1000},
           {"op":"card_diff","patch_id":"cursor_on"},
           {"op":"flush"}],
 "patches":{"cursor_on":{"region":{"x":150,"y":210,"w":8,"h":48},"fill":"black"}}}
    Semantics (server-side): the 800×480 canvas PERSISTS across ops (e-ink model); every paint op (blit/rect/card_diff) emits one frame; delay holds the last frame for round(ms / frame_budget_ms) extra frames (time is quantized to the one uniform interval, honestly); flush is a no-op here — refresh hygiene is DEVICE law (full wipe every ~20 frames unless closed_loop). rect is a server-side grammar superset op (solid rectangle, color: black|dark|light|white) so agents can compose shapes without shipping bitmaps. card_diff patches take fill:"black"|"white" or bitmap_b64 (raw 1-bit MSB-first rows, ceil(w/8) B/row × h — wrong byte count is a 422 with the arithmetic). mode → format: 1bit_partial→1bit, 4gray_partial/full→gray4. loop:n>1 materializes n repeats; loop:-1 marks the manifest closed_loop:true and the device replays.

    CAPS (server-enforced, device re-enforces — server promises are not device law): ≤120 frames · ≤60 s (count × interval) · frame_budget_ms ≥ 250 (panel physics). Over-cap → 422 with the refusing arithmetic in detail. No session → 401. Malformed JSON → 400.

    Response = the manifest (below). seq_id = sha256(canonical spec)[:16] — idempotent: re-POSTing the same spec returns the stored manifest without re-rendering.

    GET /api/frames/<seq_id>/manifest (public capability URL — the device fetches with no cookie jar)·

    {"seq_id":"00053e27d9b2a8c6","anim_id":"bounce_box_test",
 "frames":["/api/frames/00053e27d9b2a8c6/0.raw", "..."],
 "previews":["/api/frames/00053e27d9b2a8c6/0.png", "..."],
 "interval_ms":500,"format":"1bit","frame_bytes":48000,"count":5,
 "closed_loop":false,"duration_s":2.5,
 "caps":{"max_frames":120,"max_duration_s":60},"ts":1787721000.0}
    format is "1bit" (48000 B/frame) or "gray4" (96000 B/frame). URLs are tunnel-relative; the firmware prefixes its configured dashboard host (host allowlist applies device-side).

    GET /api/frames/<seq_id>/<n>.raw·

    application/octet-stream, Content-Length EXACT — 48000 (1bit) or 96000 (gray4), no padding: exact-size read = format check (byte-count honesty idiom). Bytes are canvas-space; the driver applies its own 180° + pixel-order compensation (dither.py header). <n>.png = grayscale preview of the same bytes. Cache-Control: immutable (content-addressed). Strict name whitelist; seq_id must be 16 hex chars — anything else is 404 before disk is touched.

    GET /api/frames (public)·

    Machine-readable copy of this contract (same lesson as GET /api/dither: without it the SPA catch-all serves index.html to a spec-hunting agent).

    Verified 2026-08-26 (local, live server): POST no-session→401 · contract→200 · manifest→200 · 2.raw→200 CL=48000 · gray4 0.raw→200 CL=96000 · over-cap specs→422 with arithmetic · bad seq/frame→404 · traversal→404/index (see security note). Independently re-verified same day by a second agent against the live server: POST 6-frame 1bit spec→200 manifest 694 B · GET manifest→200 694 B · 0.raw→200 exactly 48000 B · 0.png preview→200.

    Security note (found during M-A8 verify, fixed same commit): the SPA catch-all DIST / path resolved %2e%2e traversal OUTSIDE dist and served any file on disk — proven against .sticky_auth.json (jwt_secret) through the local port. Fixed with resolve-and-prefix containment; the jwt_secret was ROTATED (sessions invalidated, passkey credentials kept).

    GET /duck · GET /ansi/<seq_id> — the ANSI terminal twin (M-A8 source 4, 2026-08-26)·

    curl sticky.cagatay.my/duck — the demo that markets the thesis. The SAME stored sequences, downsampled (800×480 → 100 cols × 30 half-block rows via Pillow, from the sequences' own <n>.png previews) and streamed as chunked text/plain: clear-screen escape + xterm-256 gray half-blocks (▀, fg=top row / bg=bottom row, repeated SGR codes elided) per frame, frame delay = manifest interval_ms (~2 fps for the duck), looped to the same 60 s cap the device enforces, then reset + cursor-show and the one-line signature rendered by tiny — sticky.cagatay.my. UNAUTHENTICATED on purpose — read-only marketing: it touches no device, no owner data, only content-addressed previews that are already capability-URL public; the POST that spends CPU stays session-gated. No terminal detection: it streams the same bytes to anyone (keep-it-simple ruling in the bounded-task brief) — a non-terminal client just sees escape codes. /ansi/<seq_id> twins ANY stored sequence (16-hex id or 404 before disk); /duck is a bookmark to a built-in duck_waddle spec rendered at startup through the ordinary render_sequence() pipeline — authored in the grammar itself using the scene compound op ({op:"scene", clear:"white|black"?, shapes:[{kind:rect|ellipse,tile,color}]} — composes many primitives into ONE frame) and the ellipse primitive, both added to the server-side grammar superset alongside rect and documented in GET /api/frames.
