    Display + Rendering Stack Audit — 2026-08-25 (auditor 2, full read)·

    Files read in full: tiny_display.cpp (278L), canvas.cpp/h, font.cpp/h, sticky_display.cpp/h, tiny/tiny_display.h, plus render paths in tiny_main.cpp, tiny_node.cpp, tiny_touch.cpp, tiny_screenshot.cpp, and the card spec in docs/ARCHITECTURE.md:54-80.

    P0 — correctness / safety·

    P0-1: No display mutex — three tasks call tiny_display_render_card() concurrently. Evidence: tiny_main.cpp:129 (serial card console, app_main task), tiny_node.cpp:168/178/198 (node task), and the touch task reads s_regions (tiny_display.cpp:113-117) while renders rewrite them. Zero locking anywhere (grep mutex|semaphore → nothing). Consequences: (a) interleaved Canvas draws + SSD1677 SPI transactions (commit blocks on BUSY up to 10s, sticky_display.cpp:126) — torn frames; (b) torn button-region reads; (c) snapshot_gray8 can capture a half-drawn canvas. Fix: one render task owning the display (ARCHITECTURE.md task table line 103 already promises this — "render | core 1 | owns display"), fed by a queue; or minimally a SemaphoreHandle_t around canvas+refresh+regions.

    P0-2: The documented refresh policy does not exist. tiny/tiny_display.h:3-5 and ARCHITECTURE.md:80 promise "min 1.5s between refreshes; coalesce bursts". Implementation: every render calls sticky_display_refresh_monochrome() unconditionally (tiny_display.cpp:210); tiny_display.cpp:14-15 admits it in a comment. A burst of relay envelopes = flicker storm + panel stress. Fix: render task records last_refresh_tick; early card replaces the pending card (coalesce = keep newest), delay to the 1.5s boundary.

    P0-3: Font metrics contradiction — layout math assumes a font that doesn't exist. tiny_display.cpp:36-39 declares kGlyphW=8, kGlyphH=16. The actual font is 5x7 with advance (5+1)*scale and height 7*scale (font.h:9-11, canvas.cpp:115). Effects: text_width() overestimates 33% → button labels left of center (tiny_display.cpp:104-106); chars_per_line underestimates 25% → ~19% of usable width wasted; line pitch 38px for a 14px glyph = 24px dead leading; title bar reserves 58px for a 21px title. Sparse and small simultaneously. Fix: derive all metrics from kFontWidth/kFontHeight/kFontSpacing — or replace the font (P1-1) and keep the 8x16 cell for real.

    P0-4: Card spec v1 is ~half implemented — chart, image, composite, button objects, card_id, gray4 all missing. Implemented (tiny_display.cpp:196-206): only text/list/kv + unknown-type fallback. Specifically: - buttons as objects: draw_buttons line 96 does cJSON_IsString(b) ? b->valuestring : "?" — the spec's own example {"id":"done","label":"Done ✓"} renders as a button labeled ?. And ui_tap events post label= only (tiny_touch.cpp:78-84), never {card_id, button_id} (ARCHITECTURE.md:73) — the backend can't correlate taps to cards. This is plausibly the live label=? bug. - chart: not implemented — unknown-type branch (line 201). A bar chart is ~40 lines with fill_rect. - image: tiny_display_blit_1bit exists (line 236) but nothing calls it; no HTTP fetch path; partial flag ignored (line 238). - composite: absent. - gray4 hint: never read; every draw uses GrayLevel::Black only; mono conversion maps DarkGray→black, LightGray→white (sticky_display.cpp:63) — the 4-gray panel runs as a 1-bit panel 100% of the time. sticky_display_refresh() (gray4) has zero callers. Priority order: button-objects + card_id/button_id in ui_tap (protocol correctness, small) → chart → image fetch → composite.

    P1 — visible quality·

    P1-1: 5x7 font at 235ppi is nowhere near "iPhone-like". font.cpp is the classic 5x7 ASCII set, integer-scaled into square blocks (canvas.cpp:104-112, no smoothing; 4 gray levels unused for anti-aliasing). Fix: embed a proportional anti-aliased bitmap font (TTF converted at 2 sizes, 2bpp glyphs — 2bpp maps 1:1 onto the 4-gray canvas = free anti-aliasing). Single highest-leverage polish item.

    P1-2: No UTF-8 — Turkish text renders as garbage ?s. font_get_glyph(char) (font.cpp:117-124) treats every byte ≥0x7F as ?. "Çağatay" renders ??a?atay (two ? per multibyte char). "Done ✓" → Done ???. Fix: UTF-8 decode in draw_text + Latin-ext block for çğıöşüÇĞİÖŞÜ (12 glyphs) + symbols (✓ ✗ ° … → •). Cheap, high emotional value for this user.

    P1-3: Embedded \n in body text renders as ? glyphs. draw_wrapped (tiny_display.cpp:45-72) chunks by char count; \n inside a chunk → font_get_glyph('\n') → ?. Line 69 only catches newline at a wrap boundary. Fix: hard-break on \n (and \r) before wrap math.

    P1-4: Truncation is silent — overflow text just vanishes. draw_wrapped stops at max_y (line 52), list/kv rows break past max_y (lines 130, 146). No ellipsis, no "+3 more", no pagination. Fix: clipped content draws a …more marker; long-term page with UP/DOWN hardware buttons (GPIO5/6 already initialized, tiny_main.cpp:78).

    P1-5: Touch regions published before the frame is on glass — see TOUCH_AUDIT P0-1; the fix must pair regions+card_id with the committed frame under the render lock.

    P1-6: Partial refresh implemented in the driver, never used; no ghosting counter. sticky_display_refresh_partial() (sticky_display.cpp:186-212, correct comparison-frame trick documented) has no callers. When status bar/stream land: add s_partial_count, force full refresh every ~8-12 partials and on card-type changes.

    P2 — robustness / nits·

    • P2-1 draw_wrapped back-off loop bounded only by take=strlen clamp — comment/bound to prevent regression (tiny_display.cpp:55-59).
    • P2-2 line[128] silently truncates if chars_per_line > 127 — derive buffer from constant.
    • P2-3 snapshot_gray8 reads the live canvas, not "the LAST RENDERED framebuffer" as the header claims (tiny/tiny_display.h:20-21). Rotation IS consistent across canvas/touch/screenshot ✓. Snapshot under the render lock after a successful commit makes the claim true.
    • P2-4 tiny_display_blit_1bit = 384,000 per-pixel calls with bounds checks — row-wise byte expansion ~20× faster; matters for stream.
    • P2-5 splash() magic coordinates only center because of the wrong 8px metric; will shift when P0-3 lands.
    • P2-6 Footer reserves 26px for a 7px line — same metric bug family.
    • P2-7 kv value column fixed at 360 (tiny_display.cpp:141) — long keys overlap values; size from longest key.
    • P2-8 Unknown-type fallback paints honestly ✓ but should also carry "unsupported type" upstream in the reply.

    Status bar (clock / battery / Wi-Fi) — what it needs·

    1. Reserved strip (e.g. top 28px) the card renderer must not paint — add content_top offset (today render_card clears the whole canvas, tiny_display.cpp:172).
    2. Partial refresh — driver ready (sticky_display.h:20-23); strip must be pure B/W.
    3. Ghosting budget — full refresh every N strip updates.
    4. Data sources — sticky_battery_read() exists; tiny_wifi_is_up(); clock via SNTP or the on-board PCF8563 RTC (I2C1).
    5. The render-task/queue from P0-1 — housekeeping posts "strip dirty" events, never touches SPI.

    Polish roadmap (ranked)·

    1. Render task + queue + 1.5s coalescing lock (P0-1, P0-2) — prerequisite for everything.
    2. Region/frame atomicity + button {id,label} + ui_tap {card_id,button_id} (P1-5, P0-4a) — kills today's field bug.
    3. Font metrics truth pass (P0-3).
    4. Real font: proportional, 2bpp anti-aliased, UTF-8 + Turkish glyphs (P1-1, P1-2) — the visible leap.
    5. \n handling + …more truncation marker (P1-3, P1-4).
    6. chart card (small, high demo value).
    7. Status bar on partial refresh + ghosting counter.
    8. image card (HTTP fetch → fast blit) then stream (P2-4).
    9. gray4:true path — actually use the 4-gray panel.
    10. composite card — closes card-spec v1.
    11. Nits: kv column sizing, splash re-centering, snapshot-after-commit semantics.
