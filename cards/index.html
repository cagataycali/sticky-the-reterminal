    Cards — the render_ui spec (as shipped)·

    The card renderer (tiny_display.cpp) turns a JSON spec into the 800×480 4-gray panel. It is the view layer for everything: relay render_ui envelopes, stickyOS pages, agent answers, the provisioning screen. Design rule inherited from tiny's render_ui: no code ships in a card — only data; the firmware renders each type natively.

    Common fields on every card: title (heading), card_id (echoed by render_ui replies and page — the panel's commit receipt), footer (small line at the bottom), buttons (touch bar, below).

    Shipped card types·

    text·

    {"type":"text","title":"Dinner","body":"Back at 19:30 — pizza in fridge"}
    Word-wrapped body. Unknown card types degrade to a labelled error card — never a blank panel.

    Check 23's torture card filed two renderer findings; both were root-caused and fixed in 0.14.18 (on glass — this loop sent an id-less card and got card_id=auto-27b6c5df back). A spec without id no longer commits an anonymous card — the firmware synthesizes a stable identity (FNV-1a over type+title, rendered auto-xxxxxxxx), so the same card always gets the same id, the mirror can still correlate, and ui_tap never again reports an empty card_id (the sender gets a log warning so the habit dies too). And the orientation-collage had a real mechanism, not a missing wipe call: partial refresh is a comparison against the last pushed frame — after a rotation that baseline is a differently-oriented picture, so "unchanged" pixels survive as fragments. The fix tracks the rotation of the last pushed frame (s_pushed_rot, updated only on refresh success); any rotation delta forces the full mono wipe past every fast path. The last sibling finding — draw_wrapped's 1024-byte fold buffer cutting long bodies silently at render while scroll exists precisely to browse them — is dead since 0.14.20: the fold buffer grows on demand (2× input — the worst real fold expansion is 1.5×, e.g. ©→(c) — under a 16 KB ceiling so a hostile serial write can't OOM the render task). Past the ceiling the text ends in " [cut]" on the glass, never silently; an alloc failure renders "(no memory for text)" — the honest-void idiom again. The dashboard already compensates with a fold-budget pre-flight: a composer lint plus a server-side render_warning, warn-never-refuse (the glass still renders the first 1024 bytes honestly). The estimator mirrors ascii_fold's growth table (✓→[ok], ½→1/2, ß→2 bytes…) and applies it per field, exactly like draw_wrapped's per-call buffer — body, each list item, each composite part, recursively.

    list·

    {"type":"list","title":"Groceries","items":["milk","eggs","bread"]}

    kv·

    {"type":"kv","title":"Status","rows":{"in":"19:30","battery":"84%"}}
    rows accepts an object or [["k","v"],…] pairs.

    composite·

    {"type":"composite","title":"Morning","parts":[{"type":"kv",…},{"type":"list",…}]}
    Up to 4 parts (beyond that nothing is legible at 16×32 glyphs) sharing the body evenly, hairline separators, each part with its own small heading. Buttons/footer belong to the card, not to parts.

    qr·

    {"type":"qr","text":"WIFI:S:tiny-1a2b;T:WPA;P:tinysetup;;","caption":"scan to join"}
    Exists because typing an SSID/password off a 4-gray panel is the worst part of setup — the provisioning portal hands your phone a scannable WIFI: code instead. Modules are painted one fill_rect per dark module. Two honesty rules, because an unscannable QR looks exactly like a scannable one from across the room:

    • below 3 px/module a phone camera gives up on e-ink — instead of painting a decorative square, the card says how much room the symbol needed
    • text over the version cap → the card names the byte count that would not encode

    (Capped at 12 px/module — no point wasting the panel on a huge symbol.)

    keyboard (stickyOS)·

    On-e-ink keyboard used by the Wi-Fi join flow — rows of touch keys (shift, bksp, space, cancel, ok) editing a masked value line. Also reachable via render_ui for custom prompts; key taps route to the shell (tiny_shell_key). Long input tail-clips (0.14.5): the value line stays right-anchored so the newest characters are always visible, a ~ marks the cut, and the caret is clamped in-box — typing past ~26 chars portrait / ~46 landscape no longer overdraws.

    menu (stickyOS)·

    Tappable rows with an optional right-aligned note (e.g. Wi-Fi scan results with RSSI). Row taps route to the shell (tiny_shell_menu). Shows up to 24 items; rows scrolled out of the window are unstaged — an invisible button must not be tappable.

    Body overflow — scrolling (0.14.x)·

    A text/list/kv/menu body taller than the body box scrolls: the canvas measures full content height through its y-clip, a right-edge track+thumb scrollbar shows position, and steps draw with partial refresh. Fingers scroll by vertical swipe (rotation-aware) or UP/DOWN; agents use the scroll verb, whose reply carries the whole model (offset/content_h/view_h). A card that fits doesn't scroll and says so (scrollable:false).

    priority (0.14.4 — parsed now, semantics reserved)·

    Any card may declare "priority":"alert" (default "normal"). Today the whole behavior is a visible receipt — the title gains a ! prefix — parsed now so senders can start declaring intent and no future firmware breaks them; the real focus/queue semantics arrive with the notification model. Probed live on 0.14.4 glass.

    chart (0.14.16)·

    {"type":"chart","title":"Battery","data":[92,90,88,85,84],"style":"line","y_min":0,"y_max":100}
    Sparkline-class line/bar renderer — battery and temperature history finally have somewhere to draw. Auto-scales unless y_min/y_max pin the range, and the scale values are drawn on the axis — a chart that hides its scale is a mood, not a measurement. E-ink-tuned choices: 2 px stroke (1 px ghosts on this panel), dotted midline, first/last x-labels only (more would collide), 160-point cap. Honest-void rather than a fake plot on <2 points or when a composite squeezes it below 60 px. Additive — grammar v2 stands.

    buttons·

    Not a body — a touch bar: up to 4 buttons drawn at the bottom (56 px bar, 24 px margins, 16 px gaps, width split evenly), attachable to any card: 

    {"type":"text","title":"Dinner","body":"Pizza in fridge",
 "buttons":[{"id":"done","label":"Done"},{"id":"later","label":"Later"}]}
    A tap on a button the shell doesn't own goes upstream as a ui_tap device note → the owner's activity feed → the agent answers with the next card. The screen is a conversation.

    chat (since 0.15.2, grammar v3 — STREAMING_UI.md)·

    The iOS conversation, translated to 4-gray: user messages are LightGray-filled rounded bubbles on the right, assistant messages are outlined white bubbles on the left (radius 12, max-width the spec-exact 70% of the lane since 0.16.8/R-3 — designer-verified off a panel PNG in verdict batch #8: a long assistant bubble measured 508 px of the 752 px body lane, 67.6%, under the 526 px cap; a single short line shrinks to its own width — "Yes." is a chip, not a banner). Scrollable like every long body. 

    {"type":"chat","card_id":"ask","messages":[
  {"role":"user","body":"what's the weather"},
  {"role":"assistant","body":"Sunny, 24C."}
]}
    A streamed text ask renders as this card automatically: the question echoes as the user bubble (the receipt), and the answer types into the assistant bubble at ≤2 Hz partial refresh with a caret at the tail, then settles with one full refresh. Voice asks keep the plain text card — the device never sees its own transcript and must not invent an echo.

    image — server-rendered pixels (grammar ≥ 7)·

    {"type":"image","card_id":"my-frame","url":"https://…/frames/<sha16>/portrait_1bit.bin"}

    The device fetches a pre-dithered exact-size raw frame from a capability URL (the dashboard's /api/dither image rail or /api/frames anim rail produce them — sha-as-secret, no cookie, fetched outside the display lock) and blits it to the canvas. Shipped in 0.19.0 with the strongest receipt in the repo: the first server-rendered frame was screenshotted back and diffed against the server's own preview — 0 of 384,000 pixels differ. The dashboard's Pillow raster and the device's 1-bit expand agree bit-for-bit. Consumers gate on grammar_version >= 7 from status. One cosmetic wart, filed not hidden: the relay ack currently echoes card_id=image (the publish label) instead of your card's own id — disambiguate via screenshot until the one-line fix lands.

    Planned (not yet dispatched)·

    stream — walking an anim-rail manifest's frames through the same fetch path with partial refresh (tiny_stream_play is a header-only contract today; un-gated by M-A4's proof, next builder package). Until it lands, image covers single frames and the other types cover the practical cases.

    Refresh policy (e-ink physics, honestly)·

    what mode speed
    text / list / kv / menu / keyboard / buttons monochrome full ~600 ms class
    status-bar clock, scroll steps, frame sequences partial fastest, some ghosting
    photo-grade cards (gray4:true) 4-level full slowest, prettiest

    Minimum 1.5 s between refreshes; bursts coalesce (queue, render last). A goodbye card survives deep sleep at 0 mA — e-ink keeps the image with every rail off.
